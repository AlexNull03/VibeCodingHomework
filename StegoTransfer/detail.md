## 1. 项目概述

### 1.1 任务
构建一个"隐写加密传送"网站：用户输入口令与原文，经 PBKDF2 派生密钥、AES-GCM 加密得到 base64 密文；密文可直接作为文本传送，也可通过 LSB Matching + 边缘自适应选点隐写进 PNG 图片。接收方凭口令（与时效选项）解密还原原文。支持"密文有时效"——超过有效时间后任何人（含发送者本人）都无法解密。

### 1.2 技术核心
- **密钥派生**：PBKDF2-HMAC-SHA256，100 000 次迭代，输出 256 bit。
- **对称加密**：AES-256-GCM（12B 随机 IV，自带 16B 认证标签，防篡改）。
- **密文封装**：二进制密码帧 → 标准 base64 → **在 base64 字符串第 16 个字符后"插入"16 字符盐字段**（插入，不是替换）。
- **时效盐**：有效时间转秒数存入盐字段；真实派生盐由接收方按本机时钟计算的时间窗口现场生成。
- **图像隐写**：PNG 像素 RGB 通道 LSB Matching（±1）+ 边缘/纹理区域自适应选点。
- **实现形态**：纯静态站点（HTML + CSS + 原生 JS），Canvas API 处理像素，Web Crypto API（SubtleCrypto）完成全部密码学运算。零后端、零第三方依赖。

### 1.3 部署
- 服务器目录：`/home/alex/Work2/Trae`
- 访问地址：`https://www.alexcn.work/Work2/Trae`
- 全部资源使用**相对路径**（`./`、`css/...`、`js/...`），确保子目录托管无 404。

### 1.4 安全模型一句话
口令、明文、密钥全程不出浏览器；服务器只托管静态文件。安全靠强口令 + PBKDF2 高迭代 + AES-GCM；时效盐只保证"过期不可解"，不保证有效期内抵御截获破解。

- 一句话功能介绍：本地加密 + 图片隐写，数据不经过服务器。
- 两个入口卡片（锚点/标签页）：我要加密、我要解密。
- 免责声明要点：

  2. 仅供学习与合法用途，禁止用于违法活动；
  3. 不保证对抗专业隐写分析/取证工具；
  4. 载密图片必须以 **PNG 原文件**传送，社交软件压缩、截图、缩放、二次编辑都会导致数据损坏；
  5. 设置了有效时间的密文，**过期后发送者本人也无法解密**，请妥善安排发送时机；
  6. 忘记口令无法找回（无后门）。

### 4.2 第二段：加密区（两个模式选项卡）

**模式 A：纯文本加密**
- 输入：口令（+ 口令二次确认）、原文（多行）、有效时间（可选：60 秒 / 5 分钟 / 1 小时 / 自定义秒数，≥60）。
- 输出：base64 密文文本框 + 复制按钮。

**模式 B：图片隐写**
- 第一步：选择本地图片（任意常见格式）。上传后立即：
  1. 经 Canvas 统一转为 PNG 像素数据；
  2. 计算并展示"本图约可写入 X 个英文字符 / Y 个汉字"；
  3. 给出选图建议（见 6.5）；
  4. 预览图片。
- 第二步：输入口令（二次确认）、有效时间（可选）、原文；原文框实时显示"已用/可用字符数"。
- 提交校验：口令一致且非空、原文非空、容量不超限、有效期 ≥60s。
- 输出（同时给两样）：**载密 PNG 下载按钮** + **base64 密文文本框（可复制）**。
- 处理中按钮置灰显示进度（PBKDF2 约数百毫秒）。

### 4.3 第三段：解密区（两个模式选项卡 + 时效三态）

**模式 A：纯文本密文** —— 粘贴 base64 密文。
**模式 B：载密图片** —— 上传 PNG，先提取出内部 base64 密文（可展示），再走同一解密流程。

**时效选项（必显的三态单选）：**
- 「有时效」：盐字段按"有效秒数"解释 → 用当前时钟算窗口派生盐；
- 「无时效」：盐字段直接还原为随机盐；
- 「不选择/自动」：**先按无时效试解，GCM 验签失败再按有时效试解**（时间窗口依次尝试 当前窗口、前一窗口），以验签成功者为准。

输出：还原原文（文本框 + 复制）；有时效消息额外显示**剩余有效时间倒计时**（基于提取出的发送窗口与当前时间）。

## 5. 密码学详细设计

### 5.1 二进制密码帧布局（base64 之前）

帧内**不预留盐槽位**，字段固定、两端严格对称：

| 字节偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | 版本 `0x01` |
| 1 | 1 | 标志位：bit0 = 1 有时效，0 无时效；其余位保留 0 |
| 2..13 | 12 | AES-GCM IV（随机） |
| 14.. | 变长 | AES-GCM 输出（密文 ‖ 16B tag，Web Crypto `encrypt` 直接产出） |

所有多字节字段（仅隐写帧涉及）使用大端序。UTF-8 仅用于明文层与盐字段字符层；密码帧内部全程 `Uint8Array`。

### 5.2 盐字段 S（恰好 16 个 base64 字母表字符，不含 `=`）

- **无时效**：`crypto.getRandomValues` 生成 12 随机字节 → base64 恰好 16 字符；解密时 `atob(S)` 还原 12B 真实盐。
- **有时效**：`S = String(duration + K_DUR)` 左侧补零到 16 位十进制数字（数字字符是 base64 字母表子集；16 位可表达到 10^16 秒）。

### 5.3 插入与取出（核心，强调：插入 ≠ 替换）

加密：

```
B = base64(密码帧二进制)          // 标准 base64，长度恒 ≥ 64
C = B.slice(0,16) + S + B.slice(16)
```

- C 比 B **多 16 个字符**；B 的任何字符都没有被覆盖或删除。
- 最终输出/隐写的都是 C。

解密：

```
S  = C.slice(16,32)               // 取出盐字段（字符索引 16..31）
B  = C.slice(0,16) + C.slice(32)  // 逐字符拼接，与原 B 完全一致
帧 = atob(B)                       // 一次性解码，此后内部全程字节
```

- 中段插入不影响末尾 `=` 填充；取出复原后字符串与原 B 逐字符相同，解码必然无损。
- **严禁等长替换**：base64 每字符仅 6 bit，字符 16..31 覆盖密码帧中部约 12 字节真实数据，替换会造成永久不可逆损坏。

### 5.4 密钥派生

- 无时效：`saltBytes = atob(S)`（12B 随机盐）。
- 有时效：
  - `duration = parseInt(S, 10) - K_DUR`
  - `window = floor(Date.now()/1000 / duration)`
  - 候选窗口：`[window, window - 1]`（覆盖发送/接收跨窗口边界；浏览器经 NTP 对时，不试 +1）
  - 每个候选窗口：`saltBytes = SHA-256( UTF8(DOMAIN_SEP + ":" + (window + K_TS)) )`（32B 全用）
- 统一：`key = PBKDF2-HMAC-SHA256(口令 UTF-8, saltBytes, 100000, 256bit)` → 导入为 AES-GCM CryptoKey。

### 5.5 加密流程（发送）

1. 校验输入（口令非空且两次一致、原文非空、有效期合法）。
2. 生成 12B 随机 IV；按时效模式准备盐与标志位。
3. PBKDF2 派生密钥；`crypto.subtle.encrypt({name:'AES-GCM', iv}, key, 明文UTF8)`。
4. 组装密码帧（版本+标志+IV+加密输出）→ base64 得 B → 插入 S 得 C。
5. 纯文本模式：输出 C；图片隐写模式：把 C 作为隐写载荷嵌入 PNG，同时输出 C 与载密 PNG。

### 5.6 解密流程（接收）

1. 取得 C（粘贴框或从 PNG 提取）；取出 S、复原 B、解码密码帧，读版本、标志、IV、密文+tag。
2. 按时效选项生成盐候选列表（顺序即试解顺序）：
   - 无时效：`[随机盐]`
   - 有时效：`[当前窗口盐, 前一窗口盐]`
   - 自动：先 `[随机盐]`，失败后 `[当前窗口盐, 前一窗口盐]`
3. 逐个候选盐派生密钥并尝试 `AES-GCM.decrypt`；**验签成功即为正确解**（GCM 误报率约 2^-128，判定密码学可靠；候选列表固定、两端代码路径对称，不做多编码兜底）。
4. 全部失败时按 5.7 返回明确错误。
5. 有时效且自动模式经"有时效"分支成功时，用成功的 window 计算并显示剩余时间：`(window+1)×duration − 当前时间戳`。

### 5.7 错误分类

| 现象 | 提示 |
|---|---|
| 密码帧版本/结构异常、PNG 中无 STEG01 魔数 | 不是本工具生成的密文/图片，或图片中没有隐藏数据 |
| 所有候选盐 GCM 验签均失败（结构正常） | 口令错误；或密文已过期/双方时钟超出有效窗口 |
| 图片可读取但提取长度字段异常/比特不全 | 图片曾被压缩、截图、缩放或二次编辑，请索取 PNG 原图 |
| 时效选项手动选错 | 提示改选"自动"或另一项重试 |

## 6. 图像隐写详细设计

### 6.1 PNG 转换与像素约束
- 任意输入图先绘制到 Canvas，再 `getImageData` 读 RGBA；输出统一 `canvas.toBlob('image/png')`。
- 只修改 R/G/B 三个通道；**alpha 一律保持 255**，规避浏览器 alpha 预乘导致的色值不一致。
- 边界像素（第 0 行/列、最后一行/列）不参与（边缘梯度需要邻域）。

### 6.2 关键不变量：量化边缘图（保证收发双方候选像素集合完全一致）

朴素做法在原图上按梯度阈值选点，但 ±1 修改可能让像素梯度在接收方越过阈值，导致候选集错位。采用以下确定性方案：

1. **量化**：对每个通道值先清零低 3 位 `q = v & 0xF8`（量化桶宽 8）；由量化后的 RGB 计算亮度 `Yq`。
2. **梯度**（4 邻域简单梯度）：`g = |Yq左 − Yq右| + |Yq上 − Yq下|`，g 恒为 8 的倍数。
3. **选点**：按行扫描，选 `g ≥ EDGE_THRESHOLD(=16)` 的像素为候选；每个候选像素可嵌 3 bit（R/G/B 各 1 bit）。
4. **嵌入方向约束（保证量化值不变）**：LSB Matching 需要 ±1 翻转 LSB 时，方向不得跨量化桶——
   - `v & 0x07 == 0` 时只能 +1；`v & 0x07 == 7` 时只能 −1；其余情况随机 ±1；
   - （+1 与 −1 都能翻转 LSB，故嵌密正确性不受影响。）
5. 因为所有修改都不改变 `v & 0xF8`，**接收方重建的量化图、梯度图、候选像素集合、扫描顺序与发送方逐像素一致**，无需在图中存储选点位置。

### 6.3 LSB Matching（±1）嵌入规则
- 目标位与当前 LSB 相同：不改；
- 不同：按 6.2 的桶内方向规则 +1 或 −1（0/255 极端值夹取到合法方向）。
- 相比经典 LSB 直接置位，消除值对直方图异常，抗卡方等基础统计检测。

### 6.4 隐写帧布局（嵌入 PNG 的字节流）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 6 | 魔数 `"STEG01"` |
| 6 | 1 | 版本 `0x01` |
| 7 | 4 | 载荷长度 N（uint32 大端） |
| 11 | N | 载荷 = 密文 C 的 UTF-8 字节（纯 ASCII，长度等同字符数） |

帧头共 11 字节。比特流按"字节高位在前"展开，依次写入候选像素的 R→G→B LSB。提取时先读帧头、验魔数、按 N 读满载荷，再转字符串进入 5.6 解密流程。无需结束哨兵。

### 6.5 容量计算与选图建议

设候选边缘像素数为 E：

```
可嵌总字节   = floor(E × 3 / 8)
载荷容量 Ccap = 可嵌总字节 − 11（隐写帧头）
密文 C 字符数 = len(B) + 16
len(B)       = 4 × ceil((14 + M + 16) / 3)        // 14B 密码帧头, 16B GCM tag, M=明文 UTF-8 字节数
约束         : len(B) + 16 ≤ Ccap
反推 M_max   = floor((Ccap − 16)/4) × 3 − 30
```

UI 展示：约可写入 **M_max 个英文字符**；中文按 UTF-8 3 字节估算为 **floor(M_max/3) 个汉字**（混合输入时实时按实际 UTF-8 字节数计）。

选图建议（加密区上传后展示）：
- 容量主要取决于**分辨率 × 纹理丰富度**：高清照片、自然风景、复杂插画最优；
- 纯色截图、大面积留白、大字海报边缘稀少，容量很低；
- JPEG 来源的照片转 PNG 后嵌入没有问题，**关键是载密 PNG 输出后必须原文件传输**；
- 容量不足时按钮禁用并提示：换更大/纹理更丰富的图，或缩短原文。

### 6.6 图片模式的双输出语义
图片模式同时输出载密 PNG 与 base64 密文 C：两者内容等价（C 即图中隐藏的文本）。接收方任选其一：拿到图走"载密图片"解密，拿到文本走"纯文本密文"解密，结果一致。

## 8. 安全边界（写入免责声明的技术依据）

1. 盐不是秘密：无论随机盐还是时效盐都随密文明文存放，符合标准惯例；安全依赖口令强度与 PBKDF2 迭代次数。
2. K_TS / K_DUR 为前端公开常量，仅作混淆，不提升破解门槛。
3. 时效机制只阻止"过期解密"；有效期内密文被截获且口令被爆破，仍可被解。UI 提示使用强口令（≥12 位、混合字符）。
4. LSB Matching 仅抗基础统计检测，不抗专业隐写分析工具；本工具定位学习/演示与日常私密传送。
5. 无任何后门、无口令找回能力。
